## Objective

Restore one invariant across `website`'s message-data surfaces, stated by the architect during the research and adopted here as the thing every milestone is measured against:

- **Projection confinement**: the output of a display projection never crosses a write boundary, never seeds a control whose value can be committed, and never feeds change detection.
- **Round-trip closure**: for every stored `data` value *d* the server accepts, `stripKeys(makeEditable({data: d})).data ≡ d` modulo `_key`s and key order.
- **The flag is the mode, and a JSON submission is disposed of by the five rows** (D15, D17): a message is Components V2 iff its `flags` carry `IS_COMPONENTS_V2_FLAG` or its components include a V2 type — the predicate `validateContentRequirements` already uses (`hasStructuralV2 || hasFlagV2`, `src/utils/limits.tsx`) — and the composer shows V2 for every such message it loads (M7). A stored V2 record whose body carries content or embeds shows the composer's error (`validateContentRequirements`, existing; D15's second sentence). At the two **JSON submission** surfaces the disposition is not a function of that predicate but of the three-way cell (flag, V2 components, content/embeds), per D17's five rows (M8): no flag and no V2 components → Classic, nothing shown; V2 components without the flag and without content → V2 with the flag set and a warning; the flag over components within the schema and no content → V2, nothing shown; the flag over content or embeds without V2 components → a warning and **Classic** (the bit cleared, the body kept); V2 components together with content or embeds, whatever the flag → the user **chooses** Classic or V2 and is told what the other drops. The governing principle, his words: *"fail gracefully when no content will be lost. If content must be lost to fulfill the request, block, notify, and present the user with a choice."* On save `stripKeys` sets the bit whenever V2 components are present (structure → flag, one direction) and never clears it; the toggle to V2 sets it and the toggle to Classic clears it (D16, I-D11); after M8 every JSON submission lands a draft whose bit agrees with its mode — so the bit and the mode shown never disagree at any point in a session. **The principle reaches every door** where a draft's content, embeds or components are removed on the way to a record, not the JSON surfaces alone (D18): the doors are enumerated at M8 "Reach", and no serialiser on the persist, seed or hash paths removes a classic body on its own (M8-G). **Withdrawn premises, stated so no reader inherits them**: from rev 1 to rev 6 this plan carried the research's clause *"flags derive from structure — the V2 flag is an output of the components' structure, never an independent input"* (withdrawn at D15); from rev 2 to rev 8 it carried *"a V2 bit standing over content or embeds is refused at import"* (D5's option (a), withdrawn at D17 — the surface now warns and resolves, or offers the choice). What survives of both is the one-directional save rule above; the invariant for the architect to record is this bullet, not the research's and not rev 8's.
