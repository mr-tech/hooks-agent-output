## RIG HAZARDS PAID FOR HERE — read before trusting any run from this shape

1. **A fresh worktree has no `next-env.d.ts`.** It is gitignored (`.gitignore:86`) and generated by
   Next. Without it, `tsc -p tsconfig.json --noEmit` fails with
   `TS2307: Cannot find module '~/assets/img/product_image.png'` — a rig artefact that reads exactly
   like a product finding. Copy it in from the real checkout before typechecking.
2. **A fresh worktree has no `.env.local`.** It is untracked in the real tree. Any test importing the
   `~/utils` barrel pulls `src/constants` -> `src/env.mjs`, which throws
   `Error: Invalid environment variables` at import time and reports the file as
   `(0 test)` / `Failed Suites 1`. Copying `.env.local` in does **not** fix it — vitest does not put
   those values on `process.env` for this config. Probe the `~` alias through a leaf module that does
   not reach the barrel (`~/utils/pushSorted` was used here), or the alias check reads as broken when
   it is not. Both suite runs above ran without `.env.local` on **both** sides, so the differential is
   unaffected: the same 46 files collected in each.
3. **`node_modules` is a symlink into the real checkout.** Never run an installer (`pnpm add`,
   `pnpm install`) from inside a worktree built this way — it would write through the symlink into the
   shared tree. Nothing here installs.
4. **The comparator's worktree-prefix strip is a wildcard, and must stay one.** An earlier version
   hard-coded `cr014-(pre|post)`; run against worktrees named `cr014-prefix` / `cr014-fix` it
   stripped nothing and reported **every** tuple as changed — 570 only-in-pre, 570 only-in-post, on
   two trees that were in fact identical. A differential reporting 100% drift is an instrument
   fault, not a finding: read the paths in the output before believing it.
5. **`pushSorted`, `getUrlCode` and several other `src/utils` modules are default exports.** A named
   import of them type-checks under `noEmit` but yields `undefined` at runtime, so an alias probe
   written as a named import fails for the wrong reason. Check the export shape first.
