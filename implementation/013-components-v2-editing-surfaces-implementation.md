## QA-routed Assumption Not Checked — closure (before M7's spec)

QA's assumption: *"the extracted predicates EC-1 and EC-2 ask for can be lifted out of `MessageProvider/index.tsx` and `send/page.tsx` without changing what those components do"* — falsity signature: the extracted predicate closes over provider state beyond its argument, so it is a different function than the one the product runs.

**Read directly** (not summarized): `src/providers/MessageProvider/index.tsx`'s `detectMode` (declared inside `useValue()`, four call sites, all passing a local `tmp`/`msg`) and `src/app/message/m/[id]/send/page.tsx`'s `messageHasV2`/`showV2PatchWarning` (inline `const`s in the `Page` component body).

**EC-1 (`detectMode`) — the closure risk does not materialize, but the assumption's premise ("lift without changing what it does") is false for a different reason.**

- `detectMode`'s only captured provider state is `editableState.setMessageMode` — a side-effect call, not an input to the decision. It takes `msg` as its sole argument and computes over `msg.data` alone. There is **no hidden second input** from provider scope feeding the mode decision — so extracting a pure predicate `(msg) => mode` and calling `editableState.setMessageMode(predicate(msg))` at each of the four call sites is mechanically safe against the closure risk QA named.
- But `detectMode`'s current body is **not** the predicate M7-a needs, and lifting it verbatim would ship the bug M7-a exists to fix: `function detectMode(msg) { if (msg?.data?.components) { const isV2 = hasV2Components(msg.data.components); editableState.setMessageMode(isV2 ? 'v2' : 'classic'); } }` (i) checks structure only — `hasV2Components`, never the flag; (ii) does **nothing** when `msg.data.components` is absent or empty, even when `flags` carries `IS_COMPONENTS_V2_FLAG`. This is exactly the no-`components`-key case EC-1's own falsity signature and research G4 single out. The canonical corrected form already exists in the codebase, not in `messageMode.ts` but in `src/utils/limits.tsx`'s `validateContentRequirements` (not in the plan's file inventory, read-only reference): `hasStructuralV2 = components.some(...)`, `hasFlagV2 = !!(flags & IS_COMPONENTS_V2_FLAG)`, `hasV2 = hasStructuralV2 || hasFlagV2`.
- **Conclusion**: EC-1 does not need a different shape than QA already specified — the extracted function must implement `hasFlagV2 || hasStructuralV2` (matching `limits.tsx`'s form) rather than mirror `detectMode`'s current structural-only, guarded condition. "Extract" here means *introduce the corrected predicate at `src/utils/messageMode.ts` and call it unconditionally from all four `detectMode` call sites* (dropping the `if (msg?.data?.components)` guard), not *hoist the existing code unchanged*. No provider-state threading is required — `detectMode`'s wrapper (still calling `editableState.setMessageMode`) is unaffected by the predicate's internals.

**EC-2 (`messageHasV2`/`showV2PatchWarning`) — same underlying gap, extraction mechanically faithful to the signature QA asked for.**

- `messageHasV2 = message?.data?.components ? hasV2Components(...) : false` — structural-only, the same gap as `detectMode`. `showV2PatchWarning = showEdit && !!oldMessage && messageHasV2` — depends on `oldMessage` (from `useWebhook()`) and `showEdit` (local `useToggleState()`), both passed as ordinary values, not captured indirectly through any other provider hook.
- **Conclusion**: extracting an importable `(message, oldMessage, showEdit)` predicate — exactly the three-argument signature QA specified — is faithful with no closure hazard, provided the `messageHasV2` half of it is corrected to `hasFlagV2 || hasStructuralV2` rather than lifted as structural-only (otherwise the flag-only re-send case — a D12 import, a repaired 5712, a D16 Action-Rows toggle — silently keeps shipping without its warning, which is EC-2's own falsity signature).

**Net effect on M7's spec**: both extractions are safe against the closure risk the Assumption named. Both must fix the same underlying structural-only gap, using the disjunction already established as canonical at `limits.tsx`. This is not scope growth beyond M7-a/M7-c's stated criteria — the plan's own criteria (M7-a: "flag-only records open V2"; the both-directions obligation table's M7-a row) already require the corrected disjunction; the closure read confirms the *how*, not a new *what*.
