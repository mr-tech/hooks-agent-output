## Executive Summary

The five-file change is sound from a security standpoint and slightly improves posture: it adds a parse guard that keeps a malformed body from crashing the process, closes a page-and-promise leak, makes a browser-launch failure reach the waiting request instead of a hang or a retry storm, and — the one real security property — makes the service **refuse to start when `API_KEY` is unset**, closing a fail-open at `471578f` where an unset key made the accepted header the literal `Bearer ` (empty secret). The new shutdown path adds no privilege and no exposure: its only triggers are the PM2 IPC channel and SIGINT, both reachable only from the root daemon that owns the process.

What the host reads established is a pre-existing posture, unchanged by this release and outside the chain's scope by the owner's D6: the generator's HTTP port is **reachable from the public internet** (connect from this machine to `165.227.249.183:3000` succeeded; `0.0.0.0:3000` is bound by uid 0), the service runs as **root with every capability**, and it drives **Chromium 116.0.5845.96 with `--no-sandbox` as root** to render pages that embed **user-supplied image URLs** fetched directly. That build predates the fix for CVE-2023-4863 (libwebp, exploited in the wild, fixed in 116.0.5845.187), so a Hooks user's embed image can be a crafted WebP decoded by an unsandboxed root renderer. These findings were put to the owner through steering as a decision and accepted as recorded (rulings 2026-11-08T09:43Z, "Agent: accept, record only"); they are carried by `handoff/preview-image-generator-host-security-posture-2026-11-08.md` and are not a reason to hold M9, because the release neither widens nor narrows them and the defects it fixes are real.

**Overall Risk Rating**: LOW for the change under review; HIGH for the pre-existing posture the release redeploys (H-001).
**Verdict**: APPROVED (for `471578f..7e5ca5f`; required controls: none; recommended controls: § Required Controls).

### Informational / Best Practice Recommendations

- **I-1 — The shutdown path changes no privilege and adds no exposure** (the brief's third question). `process.on('message')` is reachable only through the IPC channel PM2 opens when it forks the app — an inherited socketpair with no filesystem path — and `pool.on('factoryCreateError')` is in-process. SIGINT to a uid 0 process needs root. Every path ends in `process.exit(0)`; the 10 s timer bounds it. The new log lines (`Server received <trigger>`, `Drain complete in Nms.`, `Drain failed after Nms: <err.message>`) carry no credential: the errors reachable there come from `server.close`, `pool.drain`/`clear` and `Browser.close`. `shutdown()` runs with the same uid, capabilities and cwd as before.
- **I-2 — M8-e closes a fail-open** (positive). At `471578f`, `src/config.ts` built `API_KEY` as `` `Bearer ${process.env.API_KEY ?? ''}` ``, so with the variable unset the accepted header was the literal `Bearer ` and any request carrying it authenticated. At `7e5ca5f` the process exits 2 before listening, and `stop_exit_codes: [2]` keeps PM2 from restarting it. `prod.yml` sets the key, so the deploy is unaffected (code review Round 18, M8-e row).
- **I-3 — For code review: `closeIdleConnections` exists on the host's interpreter.** CR-27's attack C modelled a Node before 18.2; the host runs 18.17.1 (H-003's read), so that shape does not occur there. The `7e5ca5f` fix (distinct failure line, no drain-complete on failure) stands on its own merits regardless.
- I-4 INFO RETIRED at `8de2b53` — the D36 check (`checkPoolShape()` in `src/getPool.ts`) now runs before `server.listen` in `src/server.ts`, logging a named error line and keeping the service up; it probes a never-started pool (`autostart: false`, `min 0`) so no browser is launched. No security effect. Raised against `7e5ca5f`, where the check ran at first pool creation; code review read it there (steering, 09:4xZ message).
- **I-5 — A second listener on `[::1]:3000`** (uid 997 per `/proc/net/tcp6`) is not the generator (which binds IPv4 `0.0.0.0`); unattributed, outside scope.
- **I-6 — The dependency set did not move.** `git diff --numstat 471578f..7e5ca5f -- package-lock.json package.json` is empty; the range touches only the five files. Resolved versions: puppeteer 21.1.0 (Chrome 116.0.5845.96), generic-pool 3.9.0, @aws-sdk/client-s3 3.383.0, dotenv 16.0.3. Architecture P-2 records that the security risk of these 2023 dependencies "nobody has assessed" — H-001 and H-003 are that assessment's first result (INBOX entry to the architect, § Routing).
- **I-7 — Secret scan of the tracked tree at `7e5ca5f`** (`git grep -c -i -E <pattern> 7e5ca5f -- .
